# **SECTION 3 — THE RISK-BASED DECISION FRAMEWORK**

Your system must classify all tasks into three risk levels:

---

## **🟥 RISK LEVEL 3 — HIGH RISK (Hard Stop Tier)**

Includes:

* schema alterations

* RLS policies

* production functions

* environment variable changes

* deleting files

* overwriting core logic

* migrations

* triggers

* automation loops

* security configs

**RULE:**  
 If uncertainty \> 0% → **STOP and ask**.  
 If conflict exists → **STOP and escalate**.  
 If user insists → require **explicit override safeword**.

---

## **🟧 RISK LEVEL 2 — MEDIUM RISK (Confirm Tier)**

Includes:

* major component refactors

* multi-file updates

* service rewrites

* project-level renaming

* UI restructuring

* major state logic changes

**RULE:**  
 If uncertainty \> 10% → ask 1 clarifier.  
 If conflict exists → ask user for resolution.  
 If user responds → proceed.

---

## **🟩 RISK LEVEL 1 — LOW RISK (Assume & Execute)**

Includes:

* new UI components

* small edits

* styling

* adding props

* simple logic

* non-destructive updates

* adding services

* adding files

**RULE:**  
 If uncertainty \< 20% → assume the intuitive option and execute.  
 No clarifier needed unless ambiguity is extreme.

# **SECTION 4 — THE QUESTIONING PROTOCOL (WHEN TO ASK VS ASSUME)**

To fix contradictions between “always ask” and “ask minimally”, the system uses this protocol:

---

## **Ask a clarifying question ONLY when:**

1. Safety could be violated

2. Architecture could be broken

3. Data integrity is at risk

4. Multiple interpretations lead to different schema outcomes

5. User’s instruction contradicts environment rules

6. The change affects more than 3 files

7. A dependency or API is unknown

---

## **Do NOT ask when:**

1. The task is UI, layout, or simple styling

2. You can infer meaning from context

3. META Agent blueprint is already complete

4. The user’s intention is obvious

5. The request fits within a known pattern

6. The uncertainty is harmless

---

4. **If user unavailable** → choose the smallest, least impactful safe action
